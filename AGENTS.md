# Architecture rules
- Server logic lives in `src/server/{functions,engine,maths,checks,providers,content}` and is never imported by client code; client-callable entry points are thin `src/lib/api/*.functions.ts` wrappers (no logic, no keys). Why: `src/server` is blocked from client bundles, and keys/answers must stay server-side.
- "Edge function" in docs = TanStack server function; never create Supabase Edge Functions. Why: TanStack stack.
- Shared client/server types live only in `src/shared/contracts`. Why: one contract for both sides and for external teams.
- Tables item_keys, feedback, escalations, hints, fallback_lines and turns have no browser grants or policies; read them only via server code using the admin client after a has_role check. Why: they contain answers or hidden scripts.
- Runtime tables are written only by server code; the browser has select-only grants. Why: engine is the single authority over session state.
- Content never lives in code; it is imported from a content-pack JSON via content-import. Why: content is data owned by Instructional Design.
- Never hard-code the tutor's name; read rule `tutor_display_name`. Why: name not final.
- Role grants/removals are logged to admin_audit by a trigger on user_roles; user_roles.granted_via marks auto-granted test roles. Why: no code path can skip the audit, and test roles can be cleaned up in one step.
- Content import: pure TS validate/diff (src/server/content), written via DB function apply_content_pack (service_role only). Why: one all-or-nothing transaction.
- Every tutor script except item prompts and the hook opening lives in the server-only `scripts` table; readable content tables hold only what the student sees before acting (column-level grants hide deprecated script columns). Why: scripts can reveal answers.
- Seed content lives in `content/packs/*.json` and is loaded with `bun ./scripts/load-seed.ts`, which runs the same import code, the re-import check and the leak check. Why: repeatable demo content without the import page.
- Banned-word matching is one shared function (`src/shared/contracts/banned-words.ts`) used by the pack check and the live reply check; the list is rule `banned_words`. Why: they must never drift apart.
- The lesson screen talks to the server only through `src/lib/api/lesson.functions.ts`; until the Phase 2 engine exists, `src/server/lesson/demo-path.server.ts` is the temporary fixed walk through the 8 steps and must be replaced, not extended, keeping the `src/shared/contracts/lesson.ts` shapes. Why: screens stay unchanged when the real engine arrives.
- Answers and whiteboard lines are checked only by `src/server/maths` (exact fraction arithmetic, no eval); the browser is told right/not-quite plus approved lines. Why: the maths engine is the single marking authority.
- Rules and fallback lines are read topic-specific first, then global. Why: the starter pack scopes them to the topic.
- Student pages: subject → chapters → quests → topics, built from topics.subject/chapter/quest; colours, font and tutor images are tokens/assets only. Why: restyle = token/asset swap.
- The leak check skips columns holding the student's own input and admin-only load reports. Why: a student's correct working can equal a worked-solution line.
- Dark mode rules: see `src/components/AGENTS.md`.
- Chat bubbles pass through `src/shared/contracts/chat-safety.ts`; anything that looks like raw data becomes the approved fallback line, and student answers are stored as on-screen words. Why: raw item data must never reach a student.
- Chapter card numbers, symbols and descriptions live only in `src/shared/chapters-display.ts` until they move into the content pack; open/locked comes from the topics table. Why: content stays data-driven.
- Addresses are /[subject]/[chapter]/[quest]/[topic] from DB slug columns (`src/shared/routes.ts`); old addresses are redirect-only routes. Why: readable URLs that never break.
- Every way into a topic opens its "Let's Begin" map (`.../[topic]/path`; `/intro` is redirect-only); Fiti starts the lesson from the map chat using approved `path_*` fallback lines, and the 6 drawn stops carry the 8 steps via `src/shared/path-stops.ts` (tested). Why: one way in, content stays data, and the map matches the design.
- Ask Fiti openings: `src/server/home/opening.ts` (pure, tested) picks intro / struggled / away / next_day / normal once per Lagos day; `opening.server.ts` runs the first-time talk as `meta.pending` onboard steps and saves answers to server-only `student_prefs`; only the feeling reaction is AI-written and must pass `checkAiAnswer`, else its approved line plays. Why: the AI never steers the conversation, and preferences stay out of the browser.
- Some subdirectories have their own `AGENTS.md`; read it before changing files there.
- Typed messages are sorted by `src/shared/intro-moves.ts` first and by the AI (`src/server/providers/ai.server.ts`, rule `ai_provider`) only when the word list is unsure; AI answers use only `fact_<skill>__<stage>` fallback lines and must pass `src/server/checks/ai-answer.ts`, else the approved line plays. Why: the AI never decides or reveals, and the word list keeps working when the AI is off.
- Warm-up skips use only `src/server/lesson/shown-skills.server.ts` (real, non-abandoned, post-Restart evidence) and are logged as `warmup_skipped`. Why: no skips from preview/restarted evidence.
- Home agent: messages are sorted by `src/shared/home-intents.ts` (word list) then the AI only when unsure (`classifyHomeMessage`, 3 s); the action is chosen only by `src/server/home/decide.ts` (pure, tested) and run in `src/server/home/agent.server.ts`; lines are `home_*` fallback lines; every intent/action/outcome is logged in server-only `home_messages`. Why: the AI never picks actions, topics or dates.
- Plan changes save only via `plan_yes`, which re-reads the last proposal from `home_messages`; parent/teacher `plan_items` are locked. Quiz sessions are `sessions.state.kind = 'quiz'` and are excluded from lesson progress. Why: no change without her Yes, and quizzes never look like lessons.
- Ask chat: messages belong to a server-only `home_conversations` row (New Chat = new row); tutor choices are `HomeOption` lists saved in the tutor message meta, and an option tap runs only if `pickOption` finds it offered and available. Why: the browser can never open a locked quest or replay an old choice.
- Home agent memory: each tutor question saves `meta.pending` (10 min, replaced by the next question) and her next yes/no/option reply is matched by `matchPendingReply`/`typedOptionTitle` before any sorting; `avoidRepeat` in `decide.ts` swaps a repeated tutor line for `home_pick_one` with the `clarify()` buttons. Why: Fiti must never lose track of what it asked or loop on the same line.
- Restart (restart_journey) also starts a new empty home_conversations row and resets the intro, so Ask Fiti opens clean. Why: a restart must never show a left-over conversation or pending question.

- Any student can "Start again" from the profile menu (`src/server/home/restart.server.ts`, once a minute; ends only her own open sessions and writes the same `restart_journey` audit row). After a Restart, progress reads (me, home, openings) only count sessions started after the latest `restart_journey` audit row (`src/shared/restart-cutoff.ts` + `resetAt`). On the client, Restart clears the query cache and bumps `src/lib/restart-epoch.ts`, which remounts every route (key in `__root.tsx`) and runs registered module resets. Why: Restart must give a clean slate everywhere, with no refresh.
- `public/sims/gradient-lab-v2/` is the simulation team's Gradient Lab v2 copied byte for byte (never edited; `gradient-lab-v2.SOURCE.md`); we integrate only from outside (its `?level=`/`#N` settings, `gradientlab:*` reports, and reading its screen in `lab-v2-reader.ts`); our engine marks answers via `gradient-lab-v2-checks.ts` against pack `question_sets`, falling back to lab_reported only when reading fails. Why: it must render exactly as their team built it.
- Fiti's voice: rule `voice_provider` = gemini speaks via the AI gateway Gemini TTS (`gemini-tts.server.ts`, voice/accent wording from `gemini_*` rules, mic still ElevenLabs); = elevenlabs uses ElevenLabs (`src/server/providers/elevenlabs.server.ts`, voice/model from `elevenlabs_*` rules) for speech and the mic, falling back to Edge TTS / the AI gateway on failure. It speaks only lines noted in the server-only `voice_shown` table (`voice-ledger.server.ts`); on the live server, speech uses a fetch-upgrade socket (`tts.server.ts`) because the voice library's Node socket fails on Workers. Typing of a voiced line waits for `voiceStarted` and paces to the clip; long lines are voiced per sentence via `src/shared/spoken-split.ts` (ledger notes each part); Gemini WAV is shrunk to mp3 server-side; main-voice clips are saved in server-only `voice_clips` (keyed by voice settings + text) and shared by all students; once a line starts playing, all its pieces play. There is no header voice-mute button; any saved mute is cleared on load (`src/lib/voice.ts`). Why: the live app runs on many server copies, and music must keep playing when she's muted.
- Ask Fiti opens every conversation on the "Ready to learn" page until she acts (`src/shared/start-page.ts`, tested); that page shows no Fiti bubble; his lines appear once the chat opens. Why: the start page is the first page of any new conversation.
